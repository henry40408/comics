# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Comics is a self-hosted file server for comic books, built with Rust and Axum. It scans a data directory whose immediate subdirectories are *books* and the image files inside each are *pages*. No nesting beyond one level is scanned.

## Commands

All commands run from the repository root.

- Build: `cargo build` (release: `cargo build --release`)
- Run the server: `cargo run` (serves `./data` on `127.0.0.1:8080` by default)
- Tests: `cargo nextest run` (per the user's global rule, not `cargo test`)
  - Single test: `cargo nextest run <test_name>` (e.g. `cargo nextest run auth_logout_clears_session`)
  - Integration tests live in `tests/integration_test.rs` and drive the compiled binary via `snapbox`.
- Coverage (as CI runs it): `cargo llvm-cov nextest --all-features --workspace --lcov --output-path lcov.info`
- Lint (must pass CI): `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo deny check`
- Format before committing: `cargo fmt`

The lint config in `Cargo.toml` denies `unsafe_code` and `unexpected_cfgs` and turns on a large set of pedantic Clippy lints — expect `cargo clippy` to be strict.

### CLI subcommands

- `cargo run -- list` (alias `ls`) — print books and page counts.
- `cargo run -- hash-password` — prompt for a password and emit a bcrypt hash for `COMICS_AUTH_PASSWORD_HASH`.

## Architecture

The crate is split into a thin binary (`src/main.rs`) and a library (`src/lib.rs`) so the test suite and integration tests can build routers directly.

- **`main.rs`** — CLI parsing (`clap`), tracing setup, router assembly in `init_route`, graceful shutdown, and the `list` / `hash-password` subcommands. Embedded static assets (CSS/JS/icons) are served from here with immutable cache headers fingerprinted by `?v=<hash>`.
- **`models/`** — the scan domain. `scan_books` walks the data dir in parallel (`rayon`), building `Book`s (each with a `cover`, sorted `pages`) into a `BookScan` that also holds `books_map` and `pages_map` (id → index/page) for O(1) lookups. IDs are `xxh3` hashes of the title/path salted with `seed` (`models/ids.rs`), and `seed` is derived from `COMICS_SECRET`, so a fixed secret yields stable URLs. **Scanning performs no image I/O** — `Page::new` only stats the path; dimensions are never read (a deliberate perf choice for slow disks).
- **`handlers/`** — one module per route (`index`, `book`, `page`, `thumb`, `shuffle`, `rescan`, `login`, `health`). Handlers read shared state, never block the async runtime on CPU work without bounding it.
- **`auth/`** — form-login authentication. `auth_middleware_fn` guards content routes; `config.rs` models credentials as `AuthConfig::{Some, None}`; `session.rs` holds the live sessions in memory and is what makes logout and the idle timeout enforceable; `ratelimit.rs` throttles `POST /login` and `trusted_proxies.rs` decides whose `X-Forwarded-For` may name the client it throttles.
- **`security_headers.rs`** — response-layer middleware. `hsts_layer` is a global outer layer sending `Strict-Transport-Security` only when `COMICS_HSTS_MAX_AGE` is set (off by default: comics does not terminate TLS, and a cached HSTS entry would make an HTTP-only deployment unreachable). `no_store_html` sits *inside* the auth layer and stamps `Cache-Control: no-store` + `Pragma: no-cache` on authenticated HTML, but only when the handler set no `Cache-Control` of its own — that is what keeps the image and asset routes' deliberate long-lived values intact. Page images and thumbnails are `private` (not `public`) so a shared proxy or CDN cannot keep authenticated content while the browser's own cache still makes page turns fast; the embedded assets stay `public` because they hold no user data.
- **`secret.rs`** — `Secret`, the single configured value (`COMICS_SECRET`, at least 64 hex characters / 32 bytes; longer is accepted but buys nothing, since the signed jar is HMAC-SHA256 keyed with 32 bytes and comics never builds a private jar, so the encryption half of `cookie::Key` is dead weight). Parsed by `clap` through `FromStr`, so a malformed value fails during argument parsing rather than at startup, and `Debug` is redacted so the value cannot ride along when `Opts` is formatted for a log. Two values are derived from it, each behind its own domain separator: `session_key()` (SHA-512, which is exactly the 64 bytes `cookie::Key` wants) and `id_seed()` (SHA-256, truncated to 8 bytes). The separation is not decorative — book IDs are `xxh3(seed, title)` and appear in URLs, xxh3 is not cryptographic, so the seed must be treated as public; deriving it through a hash keeps a recovered seed from leaking any cookie-signing material.
- **`state.rs`** — `AppState` shared via `Arc`: the cookie signing `Key`, the `RwLock<Option<BookScan>>`, the thumbnail cache dir, and a `Semaphore` bounding concurrent thumbnail generation.
- **`templates/`** + **`vendor/assets/`** — Askama HTML templates and the hand-written CSS/JS bundle (embedded at compile time via `include_str!`/`include_bytes!`).

### Scan lifecycle

The initial scan runs on a background thread (`spawn_initial_scan`) *after* the server starts listening, so `/healthz` answers immediately. Until the scan completes, content routes return `503`. `POST /rescan` replaces the `BookScan` in place. Always read `state.scan` through the `RwLock` and clone out what you need before releasing it (see the lock-then-drop pattern in `handlers/thumb.rs`).

### Authentication model

Auth is enabled only when both `COMICS_AUTH_USERNAME` and `COMICS_AUTH_PASSWORD_HASH` are set; otherwise the server is fully public (and logs a warning). Login verifies the bcrypt hash once, opens a session in the in-memory **`SessionStore`** (`auth/session.rs`) and issues a **signed session cookie** (`comics_session`) whose value is the store's opaque 128-bit-CSPRNG identifier and nothing else — no expiry, no username, nothing to decode, which is what the OWASP session-ID properties ask for. Expiry, `User-Agent` and creation time live in the store. The pre-store `<nonce>.<expiry>` shape is rejected, so upgrading logs sessions out once. **The signature is kept even though the identifier is looked up rather than parsed**: it does not decide validity, it separates a forged cookie from a stale one (an alert worth acting on from the noise every restart produces) and rejects junk before the store's lock is touched. `authenticate` runs three gates cheapest-first — signature, `is_session_id` shape, then the store — and returns a `Rejection` saying which failed, because a bad signature cannot happen by accident while an unknown identifier is what *every* valid cookie becomes after a restart. **Sessions do not survive a restart**, and that is the deliberate trade: a self-describing cookie survived restarts precisely because the server held no record of it, which is also why logout could not end one. The store enforces an idle window (`DEFAULT_IDLE_TTL`, 3 days) as well as the absolute ceiling (`DEFAULT_ABSOLUTE_TTL`, 7 days); the cheat sheet's 15–30 minute idle guidance is written for applications where a session is a unit of work, not a reader. A changed `User-Agent` is reported once (the digest is an `AtomicU64` and is swapped in) and never enforced, since browsers rewrite it on every major version. Capacity is 1 000 sessions and effectively unreachable — the store only grows on a *successful*, credential-gated, rate-limited login — and hitting it evicts the least recently used rather than refusing, so a full store is never a lockout. The cookie is `HttpOnly`, `SameSite=Lax`, `Path=/`, and carries `Secure` only when `COMICS_COOKIE_SECURE` is set — in which case it is also renamed to `__Host-comics_session`, since the prefix is only legal alongside `Secure`. Exactly one name is accepted, the one the current configuration issues; logout **destroys the session in the store** — the mandatory server-side half of the OWASP logout requirement, and the reason the store exists — and then sends a removal cookie built by `build_session_removal_cookie`, which mirrors every attribute (the `removal_cookie_mirrors_the_session_cookie` test is what keeps the two in step) plus `Clear-Site-Data` for the client-side half — comics never terminates TLS, so it cannot infer HTTPS, and a `Secure` cookie sent over plain HTTP is silently dropped by the browser (a startup `WARN` flags the off state when auth is enabled). The signing `Key` is derived from `COMICS_SECRET` (`secret.rs`); a restart invalidates all sessions whether or not it is set, so what a fixed secret buys is stable book and page URLs plus signature continuity, not session continuity. Every content route — including page images and thumbnails — sits behind the middleware; only `/login`, `/logout`, `/healthz`, and static assets are public. Unauthenticated `GET`s redirect to `/login?next=…` (the `next` target is validated to be same-site); other methods get `401`. `POST /login` is rate-limited to 5 attempts per client IP per 60 seconds (`auth/ratelimit.rs`, in-memory), so the 6th attempt gets `429` regardless of the password. The attempt is *reserved* (`try_acquire`) before the ~100 ms bcrypt comparison and handed back (`release`) only when the credentials verify — check-and-count in one lock, so concurrent guesses cannot all observe a stale count, while a legitimate user signing in repeatedly never exhausts the window. The key is the TCP peer address unless `COMICS_TRUSTED_PROXIES` (`auth/trusted_proxies.rs`) lists that peer — a comma-separated set of IPs and CIDR prefixes, **empty by default**. Header presence is not evidence of a proxy (the widely-copied minimal nginx snippet sets only `X-Real-IP` and forwards a client-supplied `X-Forwarded-For` verbatim), so the header is believed on the strength of who sent it, never that it exists; the previous rule inferred trust from the peer being loopback, which trusted any co-tenant process and distrusted the common sibling-container proxy. From a listed peer the client is the **rightmost** `X-Forwarded-For` entry that is not itself listed — rightmost because nginx's `$proxy_add_x_forwarded_for` and Caddy's `reverse_proxy` *append* the peer, leaving the leftmost attacker-chosen, and skipping listed hops is what makes a proxy chain work. All header *lines* are read (`get_all`), not just the first, since HAProxy's `option forwardfor` and Caddy's `header_up +X-Forwarded-For` append a line rather than extending one. Every address goes through `IpAddr::to_canonical`, so a `[::]` bind reporting `::ffff:10.0.0.5` still matches a `10.0.0.0/8` entry and a mapped hop cannot open a second bucket. Anything unresolvable — no header, garbage, or nothing but listed infrastructure — falls back to the peer, so a misconfiguration degrades to one shared bucket rather than to no limit. A dropped `X-Forwarded-For` from an unlisted peer logs a WARN once per process; a startup warning was rejected because it cannot tell whether a proxy exists and would have to cry wolf on every direct deployment. At the 10 000-entry cap the map is pruned of expired windows and, if still full, further sources are charged to a single shared **overflow** window (`Buckets::overflow`) rather than admitted untracked. All three alternatives are worse: admitting untracked makes guessing unbounded and free (one IPv6 `/64` supplies more addresses than the cap, and every admitted attempt still costs a bcrypt verify), `clear()` lets anyone already throttled reset their own budget by spraying keys, and refusing outright turns the spray into a total login lockout. Sources already in the map keep their own budgets throughout, and `release` refunds whichever window the attempt was charged to — an address with no entry of its own must have hit the overflow. The tests `auth_every_protected_route_rejects_anonymous` / `…reachable_when_logged_in` are the guardrails — keep them passing when touching routing.

**Auditable events.** `session_created`, `session_destroyed` and `session_expired` (INFO); `login_failed`, `login_rate_limited`, `session_rejected` and `session_user_agent_changed` (WARN); `session_rejected` with `reason=unknown` is DEBUG instead. Each carries `user_agent`, the login ones `ip`, and the session ones a `session` fingerprint. `session_destroyed` also carries `destroyed`, distinguishing ending a live session from a logout with nothing to end; `session_expired` carries `reason=idle|absolute`. **The level split is the point of `Rejection`**: `bad_signature` and `malformed` cannot arise by accident and are the OWASP *Detecting Session ID Anomalies* signal, while `unknown` is what every legitimate cookie becomes at restart, so warning about it would bury the log after each upgrade. The fingerprint is `SHA-256(per-process salt || identifier)` truncated to 8 bytes (`auth/audit.rs`): OWASP requires that a session identifier never be logged in cleartext, so neither it nor the salt is ever emitted. The salt is regenerated per process, which is enough to correlate one session's events within a run. Failed logins deliberately omit the submitted username and password. Pair with `--log-format json` to feed a log aggregator; the events sit at INFO/WARN, so the default `error,comics=info` filter shows them (unlike the `TraceLayer` per-request logs, which are DEBUG). There is no `session_renewed` event: the idle window slides on every request but the identifier itself is never rotated mid-session, so there is nothing to announce.

### Thumbnails

`GET /thumb/{size}/{id}` serves on-demand JPEG thumbnails (`sm`=120px rail, `md`=400px covers; any other size → 404). Generation is disk-cached under `COMICS_CACHE_DIR`, bounded by the `thumb_sem` semaphore, and runs in `spawn_blocking`. An undecodable source falls back to streaming the original bytes; cache writes are best-effort.

## Versioning & Release

- `Cargo.toml` `version` stays at `0.0.0-dev`; the real version comes from `build.rs` via `git describe` (or the `GIT_VERSION` env var in Docker builds) and is exposed as `comics::VERSION`.
- Releases are cut with `gh release create --generate-notes`. Pushing the resulting tag triggers `.github/workflows/docker.yaml`, which builds multi-arch (`linux/amd64`, `linux/arm64`) images and pushes them to GHCR. Do **not** hand-edit version fields or `git tag` manually.

## Conventions

- The Rust toolchain is pinned via `rust-toolchain.toml` (currently `1.96.0`); CI reads the channel from that file (no version is hard-coded in `ci.yml`). There is no separate MSRV — bumping the toolchain is a single edit to `rust-toolchain.toml`.
- Test fixtures live in `fixtures/data/`; the two fixture books have stable IDs (derived from the `TEST_SECRET` constant in `main.rs`) hard-coded in tests as `DATA_IDS`. Changing the secret or the derivation means recomputing them — run the binary with that secret against `fixtures/data` and read the `/book/…` hrefs off the index page.
- User-facing strings in templates/login are Traditional Chinese (e.g. the login error `帳號或密碼錯誤`).
- All configuration env vars carry a `COMICS_` prefix (`NO_COLOR` and the build-time `GIT_VERSION` are intentionally unprefixed). `main.rs` fails fast via `ensure_no_legacy_env_vars` if a retired name is still set — the pre-prefix ones (`BIND`, `SEED`, …) and the two folded into `COMICS_SECRET` (`COMICS_SEED`, `COMICS_SESSION_KEY`). Keep the `LEGACY_ENV_VARS` list in sync when adding, renaming or removing a `#[arg(env = …)]`; a silently-ignored variable is worse than a startup failure, because the fallback (a random secret) looks like it works.
